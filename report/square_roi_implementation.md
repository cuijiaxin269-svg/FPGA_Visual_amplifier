# 方形局部振动放大实现

本次实现区域显示合成，完整的运动放大 HLS IP 保持原样。没有通过改变相机分辨率或 HDMI 视口来实现选区，也没有实现裁剪计算优化。HDMI 仍为 1920×1080@30，原有 1280×800 相机画面仍在原位置，像素格式仍是 uint16 容器内的 RAW10。

## 显示与命令

HMI UART1 发送 CRLF 结尾的 ASCII 命令，例如：

```text
VIEW 1
MAGROI 42 512 272 256 1
START
```

`MAGROI` 五个整数分别是 16 位请求序号、原图左上角 X/Y、正方形边长、局部显示开关。坐标和边长整体校验、整体生效。`VIEW 0` 为原画；`VIEW 1/2` 且局部开关为 0 时为原有整帧放大；局部开关为 1 时框内放大、框外同帧原画。默认局部开关为 0，旧屏不会被发送新增控件名称。

合成帧带两像素宽的白色内边框，位置与本帧选区完全一致；边框覆盖范围属于选区内部，极小方框可能全部被边框覆盖。`VIEW 1` 不叠加固定频谱红框；`VIEW 2` 保留频谱面板及其固定红色测量框，因此最终频谱装饰像素是框外原画规则的显式例外。频谱测量区域仍是既有独立区域，不随 MAGROI 移动。

串口屏的 640×400 选区面板、原图 2:1 映射、回执控件及拖动事件设计见 [roi_hmi_protocol.md](roi_hmi_protocol.md)。比赛提交版的屏端工程见[串口屏资料](../board/hmi/README.md)。方框控件仍需按协议接入页面。

## 数据流和所有权

```text
原始帧槽 ──→ 现有整帧运动放大 HLS ──→ 未显示的输出槽
    └──────────→ PL 合成器：框外回填原画、框内保留结果
                                      ↓ 所有写响应完成
                              原有 display DMA / HDMI
```

`motion60_roi_compose.v` 使用一个 16×64-bit 短突发缓存，从原始帧读取，向输出帧按 16-bit 像素产生写掩码；框内非边框像素的 WSTRB 为零。源和目标的 4 KiB 边界以及图像行边界分别处理。地址、区域和边框标志在 START 时锁定；忙时修改、非法地址、区域越界和总线错误均拒绝或产生错误完成。总线错误后的目标可能部分写入，软件禁止显示它。

合成器连接 FCLK1/r150 时钟复位域，经 mem/S09 到 HP0 DDR，AXI-Lite 地址为 `0x43c60000`。没有复制另一套运动放大 IP。寄存器如下：

| 偏移 | 含义 |
| --- | --- |
| 00 | 只读 ID `0x524f4931` |
| 04 | 写 1 开始；读 bit0 BUSY、bit1 DONE（保持到下一次 START） |
| 08 | 错误码，0 表示成功 |
| 10 / 14 | 原始帧 / 处理结果帧地址 |
| 18 / 1c / 20 | X / Y / 正方形边长 |
| 24 | bit0 启用两像素内边框；其余位保留为零 |

`motion60_roi.inc` 与现有调度器共同管理处理任务。原帧编号、输出槽和配置版本在 HLS 启动时绑定；处理期间的拖动只替换下一任务的目标。输出槽排除显示当前槽和待切换槽，只有 HLS、合成器及输入占用者完成后才发布。

采集环不会被软件锁住。方框关闭时沿用约 60.38 帧/秒和 20 ms 期限。开启方框后只在新的隔帧采集事件启动任务，处理与频谱采样约为 30.19 帧/秒，整帧处理期限为 30 ms。滤波系数、频谱时间尺度和发布节奏随采样率调整，切换节奏时重建处理历史。方框模式要求 `BAND` 的上限不超过 15 Hz，默认 3–12 Hz 可用。频谱在该模式下的采样上限约为 15.09 Hz，超过此频率的振动可能产生混叠。

运行中检查采集写槽，方框帧送显示前再次核对。S2MM 停止后 PARK_PTR 写槽会归零，停机排空将已停止与仍在覆盖输入分开判断。出错的任务即使随后完成，也不会由排空路径发布。固件在采集 DMA、运动放大、合成和频谱模块空闲后释放忙状态，允许串口再次 `START`。JTAG 诊断字 `hmi_diagnostics[61..63]` 记录取帧间隔、最近及最大合成耗时，耗时单位为微秒。

当前合成器扫描完整帧，框内虽然屏蔽写字节，AXI 突发仍经过这些位置。因此合成新增的数据通路传输预算约为每帧 4.096 MB（原画读＋带掩码写），若每秒处理 60 帧则约 245.76 MB/s，不含协议和竞争开销。它不是按框外面积直接缩减传输的优化实现，也不是实测吞吐量。

屏幕 APPLIED 回执采用保守观察：记录显示 DMA 当前槽及元数据，等待后续完成事件，再等待两个渲染帧周期且无 underflow/framing 增量。请求序号和最近已显示序号分别上报，旧帧完成不会确认新选区。它是软件对显示通路的状态判断，物理 HDMI 图像仍需上板验收。

## 构建和上板验证

复现入口见 [README 的环境与复现](../README.md#环境与复现)。发布分支中的硬件、ARM 固件、主机测试和 RTL 仿真输入已分别与对应通过记录的 SHA-256 核对。

| 验证 | 结果 |
| --- | --- |
| 主机与 RTL | 9 项主机测试通过。RTL 覆盖全帧合成、随机背压、边框及 1920×1080 同步。 |
| 完整硬件构建 | Vivado 2025.2 完成 75 个 IP、顶层综合、布局布线和 BIT/XSA/LTX 导出。WNS +0.091 ns，WHS +0.009 ns。 |
| 最新启动包 | 2026-11-09 重新构建 ARM 应用与匹配的 BOOT，复用已验证的 BIT/XSA。BOOT 为 13,312,196 字节，SHA-256 为 `afdc23d7c0dff93b744c8210f681a04bcd25e5560a1ee2383835a336ee9ffd81`。 |
| QSPI 固化 | 2026-11-11 经 JTAG 传入 DDR 后写入 QSPI。16 MiB Flash 整片回读一致，重新上电后核对到新版应用。 |
| 串口控制 | 用 COM8 实测启停、保持边长时移动、固定位置时改变边长、关闭方框，以及固定方框时将 α 从 12 调到 24。 |
| JTAG 画面 | 实测 256×256 与 384×384 的方框，两组框外分别有 958,464 和 876,544 个像素，与对应原始帧完全一致。选区开启时输出约 30 帧每秒，验证中的单帧处理最长约 27.73 ms。 |
| HDMI 时序 | 板上数字探针读到每帧 1080 条有效行、每行 1920 像素，刷新率约 30 Hz。探针保留同步比对标志，实体 HDMI 显示待验收。 |

上板验证使用 USB 转 TTL 和 JTAG。方框版的实体串口屏拖动、长时间稳定性以及已知振幅目标的实际位移增益仍待测量。使用步骤见[串口使用说明](方框振动放大串口使用说明.md)。
