# 方形局部振动放大：屏端协议

本协议控制方框内显示既有微运动/振动放大结果、框外显示同帧原画，不进行几何缩放。`MAGROI` 是新增命令；原有 `VIEW`、`ALPHA`、`EXPOSURE`、`START`、`STOP` 保持原协议。调试串口旧的 `ROI` 仍表示频谱测量区域，与本协议的显示选区分开。

比赛提交版的屏端文件见[串口屏资料](../board/hmi/README.md)。本页描述方框功能需要新增的控件与事件。板端已用 COM8 和 JTAG 实测，实体屏的方框交互仍待接入和验收。

## 串口入口和已有接线

命令发送到 **PS UART1 经 EMIO 引出的 HMI 接口**，参数为 **115200 baud、8 个数据位、无校验、1 个停止位（8N1），不使用硬件流控**。板上的 CH340/UART0 是独立日志和调试通道，不能在该通道发送 `MAGROI` 来替代 HMI UART1。

以下仅复述仓库已经记录的板端连接，依据和历史验证范围见 [硬件与接线资料](../board/wiring/README.md) 及 [HMI 引脚约束](../src/constraints/hmi_uart_p4.xdc)：

| 板端接口 | 既有信号/引脚 | 连接方向 |
| --- | --- | --- |
| P4.3 | `hmi_uart_tx` / AH12 | 板 TX → 屏 RX |
| P4.4 | `hmi_uart_rx` / AG12 | 屏 TX → 合适的电平转换 → 板 RX |
| P4.1 | GND | 屏与板共地 |

现有 FPGA 约束为 LVCMOS33，并假定该板 Bank 10 供电为 3.3 V。屏的供电电压与 UART 信号电平分别核对；不要仅凭型号或供电电压推断屏 TX 电平。上述接线资料记录了历史使用的电平处理，不把它推广为其他屏或其他板卡的接法。

屏端保留原生命令解析和 `sendme` 页面查询响应。屏 → PS 的本协议使用 ASCII 文本加 `0D 0A`；PS → 屏的控件赋值和页面查询使用屏原生命令加 `FF FF FF`，两个方向的结束符不可混用。

## 页面和坐标

页面按横向 1024×600 设计，左侧选区面板内容区的左上角为 `(24,80)`，尺寸 `640×400`；右侧布置边长、位置、启用与运行参数。面板仅需显示选区示意和方框，不要求串口传输实时视频。

该面板对应 `1280×800` 相机内容区，不对应整个 HDMI 输出时序范围。面板与原图均为 8:5。面板的装饰边框应放在内容区外，避免将边框宽度计入坐标。

以屏幕坐标中的方框左上角 `(sx,sy)` 和边长 `s` 为准：

```text
x = (sx - 24) * 2
y = (sy - 80) * 2
size = s * 2
```

面板内容边界为 `[24,664) × [80,480)`，方框使用半开区间 `[x,x+size) × [y,y+size)`。例如面板相对坐标 `(256,136)`、边长 `128`，对应原图 `(512,272)`、边长 `256`。拖动每个屏幕像素对应原图两个像素；协议本身也接受单个原图像素的坐标和边长，供数值微调使用。

建议拖动更新上限为 20 Hz，位置未变时不发送，抬手后发送最终配置。屏端拖动和坐标草稿使用独立变量，不直接绑定下文的反馈变量。PS 保留最新待处理配置；被后续拖动覆盖的中间配置不保证显示。

建议的新增页面元素如下；坐标均为屏幕像素，现有视图、增益和启停控件需在取得屏工程后一起排版。

| 元素 | 位置/尺寸或初值 | 事件职责 |
| --- | --- | --- |
| 选区示意面板 | `(24,80)`，`640×400` | 提供 8:5 的内容坐标范围 |
| 可拖动方框 | 初始 `(280,216)`，`128×128` | 对应原图 `(512,272,256)`；限制在面板内 |
| 边长控制 | 右侧 `x=704…1000` | 可提供原图边长 128、256、512 预设及数值输入；改变后重新夹紧位置 |
| X/Y 数值显示或微调 | 右侧参数区 | 显示原图坐标，避免把屏坐标直接发给 PS |
| 局部放大开关 | 右侧参数区 | 修改草稿 `enable` 并提交整组配置 |
| 提交状态 | 右侧或底部 | 区分待处理、已显示、拒绝和故障 |
| 发送定时器 | 周期 50 ms | 仅在拖动且草稿变化时发送；抬手事件另外执行最终发送 |

页面事件逻辑如下，这是语言无关的算法说明，不是声称已在某版编辑器编译通过的屏脚本：

```text
拖动事件：
    保持屏上方框宽高相等
    sx = clamp(sx, 24, 664 - s)
    sy = clamp(sy, 80, 480 - s)
    draft = ((sx - 24) * 2, (sy - 80) * 2, s * 2, enable)
    若 draft 变化，设置 dirty

50 ms 定时事件：若 dragging 且 dirty，执行提交
抬手事件：刷新 draft，再执行最终提交
数值/边长/开关确认事件：完成范围检查后执行提交

提交：
    对一个不同的新 draft 分配 seq = (上一新请求序号 + 1) & 65535
    对相同内容的重发沿用原 seq
    将 seq/x/y/size/enable 转为十进制 ASCII 字符串
    串口输出 "MAGROI " + seq + " " + x + " " + y + " " + size + " " + enable
    串口输出字节 0D 0A
    保存本地 latest_sent_seq，清除 dirty
```

首次创建页面时，可将下面的固定测试指令放到一个独立测试按钮的释放事件中，验证屏幕到 PS 的命令路径；它仅发送前述 `(512,272,256)` 示例，不能代替动态拖动脚本。`printh` 发送方式沿用仓库已有的实体屏测试方法（`board/scripts/original_v18/hmi_helpers.tcl` 的 `hemit`）。应在新版屏工程已建立所有反馈对象后测试，并按当前 `roi_seq` 选择未使用的新序号。

```text
printh 4D 41 47 52 4F 49 20 34 32 20 35 31 32 20 32 37 32 20 32 35 36 20 31 0D 0A
```

## 屏幕发送到 PS

```text
MAGROI seq x y size enable\r\n
```

例如实际发送 ASCII `MAGROI 42 512 272 256 1` 后跟字节 `0D 0A`。文档中的 `\r\n` 是终止字节说明，不是反斜杠加字母的四个文本字符。

| 字段 | 范围 | 意义 |
| --- | --- | --- |
| `seq` | 0…65535 | 请求序号，每次新配置加一并按 16 位环回 |
| `x` | 0…1279 | 原图选区左上角 X |
| `y` | 0…799 | 原图选区左上角 Y |
| `size` | 1…800 | 正方形边长 |
| `enable` | 0 或 1 | 是否启用该局部显示选区 |

还必须同时满足 `x+size≤1280`、`y+size≤800`。即使 `enable=0`，坐标和边长也必须有效。在 `VIEW 1/2` 下，`enable=1` 表示框内振动放大、框外原画；`enable=0` 恢复原有整帧振动放大。`VIEW 0` 始终显示全原画。本字段不等同于 `STOP` 或 `VIEW 0`。

命令必须恰好包含命令名和五个十进制无符号数，字段之间恰好一个 ASCII 空格；禁止额外字段、尾随空格、符号、小数。前导零允许。整组参数通过范围检查后才交给控制逻辑，禁止逐字段部分应用。残缺包、超长包和传输错误沿用现有解析器的 CRLF 重同步规则。

序号比较由控制层处理：相同序号与相同内容是幂等重试；相同序号与不同内容拒绝；旧序号拒绝。16 位环回按半范围规则比较，不要同时保留 32768 个以上未确认请求。屏端重启或重连后，先读取 PS 同步回来的当前 `roi_seq`，从其加一继续，不在同一 PS 启动周期中任意把序号归零。首次建立 ROI 控制且 PS 尚未接受过配置时可以从零开始。

## PS 回写屏幕

回写使用现有屏原生命令，每条以 `FF FF FF` 结束。不是自定义 ASCII `ACK` 文本，也不要求屏幕实现通用串口字符串解析器。例：

```text
page0.roi_seq.val=42       [FF FF FF]
page0.roi_status.txt="QUEUED" [FF FF FF]
```

### 必须保留的原有页面合同

**新增 ROI 对象必须叠加在原有页面合同之上，不能只建立 `roi_*` 对象。** 固件即使从未收到 `MAGROI`，仍会同步下表的旧控件；缺少它们会产生屏原生命令的对象/属性错误，并可能反复触发页面查询。对象名称和属性必须与表中一致；控件可以重新排版，也可以用支持同一属性的变量或隐藏控件保留接口。

主页面必须是 **页面编号 0、名称 `page0`**。现有协议将编号 1 视为启动动画页，编号 2 视为数字键盘页；不能把选区主页面移到这些编号或其他编号而期望现有固件自动识别。仅做单页新版界面时可使用 `page0`，但仍须保留下表全部对象和原生 `sendme` 响应。

以下类型要求来自固件实际使用的属性；可见控件的具体外观不受限制。

| 必须存在的属性 | 类型/能力要求 | 固件写入值的含义 |
| --- | --- | --- |
| `page0.vstatus.txt` | 文本 | 视图控制状态 |
| `page0.astatus.txt` | 文本 | 放大参数控制状态 |
| `page0.estatus.txt` | 文本 | 曝光控制状态 |
| `page0.rstatus.txt` | 文本 | 启停控制状态 |
| `page0.mode.val` | 整数数值 | 当前目标视图：0 原画、1 放大无频谱面板、2 放大带频谱面板 |
| `page0.alpha.val` | 整数数值 | 当前目标放大参数，0…50；首次连接/重连时同步 |
| `page0.exposure.val` | 整数数值 | 当前目标曝光参数，1…898；首次连接/重连时同步 |
| `page0.raw.val`、`page0.mag.val`、`page0.panel.val` | 支持 `.val` 的数值或选择控件 | 各为 0/1，分别表示目标视图是否为 0、1、2 |
| `page0.hgain.val` | 支持 `.val` 的数值或滑条控件 | 当前目标放大参数，0…50 |
| `page0.p0.val`、`page0.p12.val`、`page0.p50.val` | 支持 `.val` 的数值或选择控件 | 各为 0/1，分别表示目标放大参数是否恰好为 0、12、50 |
| `page0.hexp.val` | 支持 `.val` 的数值或滑条控件 | 当前目标曝光参数，1…898 |
| `page0.run.val` | 支持 `.val` 的数值或选择控件 | 已确认运行状态：1 运行、0 未运行 |
| `page0.runreq.val` | 整数数值 | 启停状态为 `WAIT ACK` 时表示请求的运行状态，否则为已确认运行状态，均为 0/1 |
| `page0.vack.en`、`page0.aack.en`、`page0.eack.en`、`page0.rack.en` | 带 `.en` 属性的定时器 | 对应视图、放大参数、曝光、启停的屏端等待定时器；固件在状态不再为 `WAIT ACK` 时写 0 关闭，是否启动及事件内容由屏脚本负责 |

旧状态文本取自 `hmi_status_text`：`SET`、`QUEUED`、`WAIT ACK`、`APPLIED`、`RUNNING`、`STOPPED`、`BUSY`、`REJECTED`、`ERROR`。文本容量须容纳这些完整字符串。`.val` 对象必须使用数值类型，不能仅创建同名的文本对象。

若保留数字键盘页，固件在编号 2 页面显示期间仍可写 `page0` 的四个状态文本、`mode.val` 和 `runreq.val`，这些属性必须按所用编辑器的规则允许跨页访问；其他草稿与私有控制值在回到主页面后同步。旧按钮/滑条的事件仍发送原有 `VIEW`、`ALPHA`、`EXPOSURE`、`START`、`STOP` 命令；仅创建上述属性并不会自动生成按钮事件。

### 新增 ROI 反馈对象

在保留上述旧对象后，在 `page0` 额外建立下列对象；数值反馈可使用变量控件，文本状态使用文本控件。这些是反馈值，不能直接充当用户正在拖动的草稿坐标。

| 属性 | 含义 |
| --- | --- |
| `page0.roi_seq.val` | 当前保留请求的序号 |
| `page0.roi_x.val`、`page0.roi_y.val` | 当前保留请求的原图坐标 |
| `page0.roi_size.val`、`page0.roi_en.val` | 当前保留请求的边长、启用状态 |
| `page0.roi_aseq.val` | 最近已完整显示配置的序号 |
| `page0.roi_ax.val`、`page0.roi_ay.val` | 最近已完整显示配置的坐标 |
| `page0.roi_asize.val`、`page0.roi_aen.val` | 最近已完整显示配置的边长、启用状态 |
| `page0.roi_valid.val` | 是否已有有效的实际显示回执；为 0 时忽略 `roi_a*` |
| `page0.roi_status.txt` | 控制层状态，如 `QUEUED`、`WAIT ACK`、`APPLIED`、`BUSY`、`REJECTED`、`ERROR` |

`APPLIED` 不能仅因收到串口命令或写入 HLS 参数而产生。实际显示回执应跟随输出帧缓冲区，在相应帧按设计要求完整显示后更新。若 `roi_aseq` 落后于 `roi_seq`，表示旧配置已经显示、较新配置仍待处理，屏端不得用旧回执覆盖当前拖动草稿。屏端还必须将回执的 `roi_seq` 与自己的最新已提交序号比较：已进入串口发送队列的旧批次仍可能在新请求发送后到达，旧序号不能清除新请求的等待状态。只有 `roi_valid=1`、`roi_seq=最新已提交序号`、`roi_aseq=roi_seq` 且状态为 `APPLIED` 时，才能把最新请求标记为已显示。

一批回写将数值字段先入发送队列、状态文本最后入队；串口发送仍为顺序命令，不是屏内部的原子事务。屏端消费回执时应以收到更新后的状态和序号为准，不能把传输中途的新旧字段混合作为完整状态。发送队列满时控制器保留待发送状态，下次从最新快照重新生成，不缓存过时的 `APPLIED` 文本。

为兼容现有屏工程，仅在 PS 收到首条有效 `MAGROI` 并将 ROI 状态标记为已使用后，才向上述新增对象写值。启动动画页和数字键盘页不接收该批 ROI 回写；回到主页面及重连时重新同步。新页面应先创建所有新增对象，再启用发送 `MAGROI` 的事件脚本。

## 固件接口与验证

`hmi_request` 保持原有三个字段，`HMI_FIELDS` 保持四组，避免改变旧控制代码的聚合初始化。ROI 单独使用：

```c
typedef struct { uint32_t seq,x,y,size,enable; } hmi_roi_config;
typedef struct { hmi_roi_config config; unsigned valid; } hmi_roi_request;
void hmi_link_set_roi_handler(hmi_link *, hmi_roi_request_fn);
```

ROI 回调沿用 `hmi_link_init` 的业务上下文；独立解析器可调用 `hmi_parser_set_roi_handler`。业务层在 `hmi_device_state.roi` 中维护 `target`、`actual`、`seen`、`applied_valid`、`status` 和 `generation`，每次状态变化递增 `generation`。语法无效的 ROI 请求也进入独立回调，但 `valid=0`，不得将它视为有效配置或启用新控件反馈。

`sim/tests/test_hmi_protocol.cpp` 覆盖旧命令兼容、字段数和数值边界、方框越界、分片/超长/断流重同步、ROI 回调上下文、旧屏无新增属性写入、发送背压后的最新快照、请求与实际序号分离、键盘页保护及重连同步。屏端拖动响应、20 Hz 实际体验、映射与 HDMI 可见结果需要实体屏和新硬件产物另行验收。
