# FPGA_Visual_amplifier 设计报告（已有材料整理版）

项目中文名：区域相位运动放大与微振检测。整理日期：2026-10-30。

本报告依据现有源码、构建报告及验收记录整理，属于待作者补充审定的设计材料。目标提交源码以 `v19boot` 为起点；历史 `v18hmi` 的整机记录与 `v19boot` 的固化记录分别保存。2025.2 迁移后的编译和实测结论以对应新报告为准，历史结果不自动转移到新产物。

## 1. 应用目标与目前实现

工程把相机图像采集、区域运动放大、频谱显示和触屏交互组合到 Zynq-7000 平台，用于观察画面中的微小运动，并显示相应频谱信息。现有资料已能说明系统实现，但尚不足以量化其在特定应用中的检测精度、优势或创新程度。

需要作者补充的内容包括目标使用场景、现有方法及文献、与已有方案的差异、代表性实物实验，以及放大参数和实际位移放大效果的定量关系。界面参数 `alpha=50` 是算法设置，不能直接作为已测得的物理位移放大 50 倍。

## 2. 硬件与软件组成

| 部分 | 现有实现与来源 |
|---|---|
| 目标器件 | `xc7z100ffg900-2`；原约束注明 OS-ZYNQ7100 Dock Lite / REV_A 核心板 |
| 图像输入 | OV9281；PS 配置传感器，PL 处理 CSI 接收及帧数据；`src/ps/capture.h` 定义 1280×800 帧布局 |
| PL 计算 | 运动放大、ROI 和频谱等自定义导出 IP；源码与导出 IP 的对应范围见 `hls_provenance.md` |
| 视频输出 | HDMI 1080p30；原画、放大无面板、放大带频谱面板三视图 |
| 控制软件 | ARM Cortex-A9 裸机程序，含摄像头配置、任务调度、视频状态和串口屏交互 |
| 人机交互 | PS UART1 经 EMIO 接串口屏；板上实体键可切换视图；UART0 为独立日志通道 |
| 启动 | 历史 v19 使用 QSPI0 第一片 16 MiB Flash；FSBL、位流和应用组成启动镜像 |

主要源文件分布：

- `src/rtl/`：CSI 数据通路、相机时钟、显示、频谱叠加及像素域复位等 RTL。
- `src/ip/`、`src/bd/`、`src/constraints/`：导出 IP、Block Design 和引脚/时序约束。
- `src/ps/`：传感器驱动、运动处理调度、HMI 协议及 UART 驱动。
- `src/hls/`：从原工程追溯的算法源；完整 IP 重生成的状态另见来源报告。
- `sim/`：主机测试与 RTL 仿真；`board/`：历史板端证据与操作资料。

## 3. 软硬件划分与接口

从现有实现可归纳出：PL 承担持续的视频数据处理和显示通路，PS 承担参数配置、外设协议和任务状态管理。这个划分使触屏通信、相机初始化和处理/显示提交分别有明确的完成条件。详细吞吐量、总线带宽与 CPU 占用的比较依据仍需补充，现有实现本身不能代替划分方案的定量论证。

`capture.h` 定义了 133-word 采集 mailbox，并使用静态断言固定结构大小；HMI 诊断使用独立空间。迁移时需要同时核对硬件地址、寄存器布局、PS 初始化和软件使用的 ABI，保持硬件平台与应用配套。

HMI 命令包括 `VIEW`、`ALPHA`、`EXPOSURE`、`START`、`STOP`。文本以 CR LF 结束，原生屏幕指令还涉及二进制结束符。协议的实际应用状态由板端处理结果反馈：

| 操作 | 现有语义 |
|---|---|
| `VIEW 0/1/2` | 原画、放大无面板、放大带频谱面板；停止状态下切换不隐含启动 |
| `ALPHA 0..50` | 配置读回且新处理帧完成后才确认已应用 |
| `EXPOSURE 1..898` | 停止时排队，下次启动读回一致后确认；运行中返回忙状态 |
| `START` | 相机、处理和显示链路就绪后报告运行 |
| `STOP` | 排空相关任务并取消待执行重启后报告停止 |

业务操作在主循环执行，中断负责接收和发送。协议不带请求序号，因此它保证已设计范围内的最终状态一致，不能据此声称可逐条关联任意高速交错请求。历史启动默认状态为 STOPPED、VIEW 2、alpha 12、曝光 320。

## 4. 已有优化及故障处理证据

以下为已记录的工程改进，不替代同条件性能对比：

| 问题或观察 | 已记录处理 | 可支持的结论 |
|---|---|---|
| UART 短包停留在 FIFO | RX 触发阈值为 1，中断内排空 FIFO | 对应主机测试及真实串口命令测试通过 |
| MMU 关闭时非对齐数值回包出错 | ARM 构建保留 `-mno-unaligned-access` | 对应版本重测通过；不是所有平台的通用编译要求 |
| 空闲超时中断负担 | 禁用 RX 空闲超时，保留接收中断 | 同曝光条件下用户报告频谱显示改善；尚无定量频谱精度增益 |
| QSPI 工具退出码未反映实际停滞 | 结合传输、Flash 读回及真实冷启动验证 | 最终 v19 镜像读回与一次冷启动通过 |
| 复位后的 DDR 遥测可能继承旧值 | v19 启动代码清零保留区并初始化中断/计时器状态 | 有专门交接和冷启动证据；不代表任意运行中系统的热跳转都受支持 |

原始说明位于 [v18 验收记录](original_notes/v18hmi/acceptance.txt) 和 [v19 验收记录](original_notes/v19boot/acceptance.txt)。可复用方法整理于 [技能包](../skill/README.md)。

## 6. 验证结论与边界

本轮整理后，现有 8 项主机测试、AMD 2025.2 配套编译器的 ARM 应用构建、Vivado 2025.2 的频谱 UI RTL 比对均已有通过记录；完整硬件构建已完成 71 个 IP 和顶层综合、布局布线及 bit/XSA/LTX 导出。随后以新 XSA 生成并编译 FSBL，BOOT 镜像 13,357,152 字节，三分区、应用载荷、UART0/QSPI 配置及新平台初始化文件匹配检查通过。具体命令、源码哈希及退出码见 [证据索引](evidence_index.md) 和[启动包报告](../build/reports/boot_2025_2/README.md)。未执行新产物的上板、烧录或冷启动；完整 HLS C++ 到 IP 重生成也尚未验证。

历史 v18 记录支持部分实体操作确认、约 10 分钟真实 UART 自动交互，以及一次连续 32 分钟固定参数运行；完整 17 项物理验收未全部通过，60 分钟测试也未完成。历史 v19 记录支持 Flash 固化及一次真实断电冷启动，当时没有相机、HDMI 或串口屏，不能据此确认外设链路。
