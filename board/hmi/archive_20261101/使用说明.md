# 单页显示与采集控制

打开 `motion60_control.HMI`，在 USART HMI 的“调试”窗口中运行。
编辑画布上的点击用于选中控件。生成 TFT 不会自动改变实体屏。

操作界面只有一页，保留原开机视频及视频结束后进入 `page0` 的行为。
使用中性灰、白色工作分区、石墨色标题栏及蓝色选中反馈。
赛事与 AMD 标识从原设计中按原像素保留。
左区直接选择外接屏内容，右区调节相位增益和相机曝光，底部提供 START/STOP，没有多页导航。

- 左区：原画面 / 放大画面 / 详细参数，控制另一块显示屏的显示内容。
- 右上区：相位增益 α，范围 0–50；支持加减、带刻度的滑条和 0/12/50 预设。
- 右下区：相机曝光，范围 1–898 行，默认 320；支持加减、滑条和“应用”。
- 底部：一个 START/STOP 切换键，在按下时发送一次命令并切换下一次操作，松开不重复发送。
- 点击 α 或曝光数字进入同风格数字输入框。首个数字替换旧值，可清空、退格、取消。
- α 确认后发送一次 ALPHA 并同步滑条/预设；曝光确认只保存本地值，按“应用”才发送曝光命令。
- 空输入或超出范围时停留在输入框并提示修改；取消不修改参数，也不发送串口命令。
- 模式按钮按下时立即互斥高亮，修复按住新按钮时旧按钮仍高亮的问题。
- 增益滑动期间只更新本地设定，松开后发送一次增益命令。
- 曝光加减和滑动只更新本地设定，按“应用”才发送命令。
- 已去掉区域定位、拖动地图、方向键、波形、频谱及多页导航。

## 必须完成的主控对接

现有交接包中 `motion60.c` 支持 `ALPHA value`，其含义是相位增益，
不是图像宽高的几何缩放。屏端已按用户要求扩展到 0–50，默认仍为 12。
**2026-10-25 交接固件解析器和算法门限仍为 30；若仍使用该固件，31–50 会被拒绝，
需要主控与算法同步支持，不能仅凭屏端上限宣称实际已生效。**

相机接口已从交接包 `zynq/sw/motion60.c:290–315` 与
`zynq/docs/MOTION60_BRINGUP.md:120–129` 核实：
`EXPOSURE` 接收整数曝光行数 1–898，默认 320，当前固定传感器模式每行约 18.2 μs。
这不是通用毫秒范围；320 行约 5.824 ms。
使用顺序为 **STOP → 等设备停机 → 调整曝光并应用 → START**。
旧固件忙碌或运行时会拒绝曝光命令，接受后在下一次 START/RECORD 配置相机。
串口屏不会假定 STOP 已完成，也不会自动连发 STOP、EXPOSURE、START。

**三种画面的切换命令是新增接口约定，现有交接固件没有实现。**
应把以下入口接到当前实际工程中实体按键使用的切页逻辑：

| 屏幕发出的文本 | 应执行的操作 |
|---|---|
| `VIEW 0\r\n` | 原画面 |
| `VIEW 1\r\n` | 放大画面 |
| `VIEW 2\r\n` | 详细参数 |
| `ALPHA 12\r\n` | 相位增益设为 12；替换数值即可调节 |
| `EXPOSURE 320\r\n` | 停机时提交 320 行曝光，下次 START 生效 |
| `START\r\n` | 开始连续运行；按下时发送 |
| `STOP\r\n` | 请求停止；按下时发送，停止完成需设备确认 |

不能仅靠在串口屏中新增按钮就替代未接入串口的实体按键。
本轮不改写或烧录 ARM/FPGA。当前实际按键工程的寄存器、控制通道和串口接线
需要与该约定对应；不得凭旧交接包猜测按键所控制的硬件地址。
详细接口见 `protocol.json`。

## 状态

`mode` 初始为 255，三个画面按钮都不选中，避免把默认值冒充实际输出。
增益初始显示 12、曝光初始显示 320，均为本地设定值；启动不会自动向主控发送任何指令。
按钮高亮表示操作选择，不代表外接显示屏已经切换。
`runreq` 保存上次请求的启停状态。0 对应按钮显示 START，1 对应显示 STOP。
按钮按下即翻转，主控拒绝或未确认不会被显示为真实 RUNNING/STOPPED。
数字输入返回后保留启停选择、显示模式、增益及曝光，主界面仍只有一个操作页。
临时 `keypad` 输入页没有额外导航菜单，不改变原 page1 开机视频。

- `SELECT`：尚未选择显示画面。
- `SET`：本地增益设定；尚未发送或未确认。
- `WAIT ACK`：命令已发送，等待设备确认。
- `NO ACK`：3 秒内没有收到适配后的设备确认。
- `APPLIED`：只允许主控在实际生效后写入，屏端事件不会自行设为这个状态。
- `READY`：操作按钮可用，不表示主控已经停机。
- `QUEUED`：仅允许主控确认曝光已接受后写入，等待下一次 START 应用。
- `RUNNING` / `STOPPED`：仅允许主控在真实运行/停机状态确认后写入。

画面、增益、曝光、START/STOP 各自有独立的确认计时器，互不覆盖。
主控实际完成画面切换后，发送：

```text
page0.vack.en=0
page0.vstatus.txt="APPLIED"
```

实际完成增益设置后，发送：

```text
page0.aack.en=0
page0.astatus.txt="APPLIED"
```

曝光命令被接受后回传：

```text
page0.eack.en=0
page0.estatus.txt="QUEUED"
```

主控在 START 后实际应用曝光，可继续写 `page0.estatus.txt="APPLIED"`。
运行确认用 `page0.rack.en=0` 和 `page0.rstatus.txt="RUNNING"`，
再写 `page0.runreq.val=1`、`page0.run.val=1` 同步下一次操作为 STOP；
停止完成后用 `page0.rack.en=0` 和 `page0.rstatus.txt="STOPPED"`，
再写 `page0.runreq.val=0`、`page0.run.val=0` 同步下一次操作为 START。

每条主控到屏幕的指令后追加 `FF FF FF`。屏幕到主控的文本以 `CR LF` 结束。
当前旧固件的普通终端日志不是上述确认指令，不能直接当作屏幕状态回传。

## 构建、证据与回退

使用项目根目录 `build_singlepage.py` 构建；`--artwork-only` 只生成预览，
`--compile-only` 复用已有控件，重新写事件并官方编译。

`control_preview.png` 是待选状态的界面合成图；
`control_selected_preview.png` 展示放大画面选中时的样子，不代表设备实测。
`verification.json` 记录官方编译、校验、几何、事件回读和逻辑检查。
硬件证据独立记录，未做的板端联调不会标成完成。

旧三页工程保留在 `threepage-locator`。修改前完整备份位置见
`backups/LATEST_SINGLEPAGE_BACKUP.txt`，备份清单逐项保存 SHA256，
可以运行备份目录中的 `restore.ps1` 恢复；实体屏回退需重新下载旧 TFT。
去除侧栏前的单页版本另存于 `backups/LATEST_FULLWIDTH_BACKUP.txt` 指向的目录。
