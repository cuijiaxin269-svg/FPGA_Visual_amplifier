# 串口控制与设备状态验证

适用于裸机 UART 驱动、触屏控制以及“命令收到”和“设备完成”存在时间差的系统。

## 输入与验证流程

准备协议格式、设备状态表、驱动实现、异常输入样本和可观察的完成信号。按下面顺序定位问题，每层通过后再推断后一层：

1. **接收层**：记录真实 RX 字节、FIFO/软件环缓冲计数和中断状态，分别发送短包、分包、粘包及含二进制结束符的数值回复。完成判据是字节完整进入解析器，而不仅是触发过中断。
2. **解析层**：测试空值、越界、超长行、错误结束符与下一条合法命令。完成判据是无误执行且后续合法输入能够恢复；保留最小失败输入。
3. **调度层**：测试重复启动、启动中停止、停止中参数更新和快速视图切换。完成判据是最终请求和真实设备状态一致；对已知过期结果明确丢弃规则。
4. **确认层**：按设备完成信号发布结果。寄存器参数写入、总线发送成功、画面帧提交分别是不同事件。完成判据由具体命令定义，例如参数读回与新处理帧都完成后再确认应用。
5. **物理层验证**：自动命令测试后，另做真实按钮、触屏和画面观察。完成判据是记录了物理操作与观察，不能把自动 UART 测试计成手指触摸测试。

可复用的测试记录字段：`firmware_hash / raw_rx / command / expected_state / actual_state / completion_event / error_counters / elapsed_time / observation_method`。

## 来源与已验证效果

来源为 [v18 原说明](../report/original_notes/v18hmi/readme.txt) 和 [验收记录](../report/original_notes/v18hmi/acceptance.txt)。原工程发生过短包滞留、关闭 MMU 时编译器生成未对齐读取、空闲超时中断占用等问题。对应修正包括单字节 RX 触发、中断内排空 FIFO、`-mno-unaligned-access`、关闭本实现不需要的空闲超时中断。

修正后的对应版本通过协议/UART/调度主机测试、五类真实命令闭环和 602631 ms 的 30 轮自动交互。用户另行确认了部分视图、增益拖动、曝光及实体键操作。所有 17 项物理验收未全部覆盖；现场频谱“改善”是主观观察，未据此给出精度提升百分比。

## 失效条件和局限

触发阈值、超时策略和未对齐访问选项取决于目标 UART、CPU 内存属性及负载，不能直接复制为所有平台的固定配置。本协议没有请求序号，不能逐条关联任意高速交错请求。电平、接地、线长等应按目标硬件核实。相关方法在本项目中有验证，尚无跨平台量化效果。
