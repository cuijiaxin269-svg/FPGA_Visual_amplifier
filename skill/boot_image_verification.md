# 启动镜像与冷启动验证

适用于新建或修改由硬件平台、初始化代码、引导程序和应用组成的嵌入式启动包。按改动范围选用检查步骤；当前已可用的整机无需为使用本指南重新验收。这里提供方法，不提供通用 Flash 烧录程序。

## 输入与验证流程

1. **组成绑定**：列出硬件平台、位流、初始化文件、引导程序和应用的来源与哈希，核对设备型号、加载地址、入口、启动顺序和存储容量。完成判据是组成项配套且静态检查通过。
2. **传输检查**：记录工具原始输出和实际传输进度，并用长度与校验值确认目标缓冲中的内容。完成判据是镜像完整到达目标，而非仅看进程退出码。
3. **存储验证**：在明确授权的编程流程中保存写入范围和原内容恢复依据，校验目标存储读回；如只改部分存储，还需核对未涉及区。完成判据是读回与预期相符，失败保留原始证据。
4. **真实冷启动**：在实际断电/上电后，读取启动模式、应用身份和运行状态；检查过程应避免重新下载或复位造成新的启动路径。完成判据是能区分 BootROM 自启动与调试器辅助加载。
5. **业务验证**：分别验证相机、显示、控制等实际业务，再做重复上电与稳定性检查。完成判据按业务测试表逐项记录，不由一次冷启动推断整机功能。

可复用的记录字段：`image_length / image_hash / component_hashes / flash_id / write_range / transfer_check / readback_check / untouched_range_check / boot_mode / application_identity / peripherals_present / repeat_count`。

## 来源与已验证效果

来源为 [v19 原说明](../report/original_notes/v19boot/readme.txt)、[验收记录](../report/original_notes/v19boot/acceptance.txt) 和 `board/results/v19boot/`。该项目两次工具调用在主机传输阶段停滞，原记录指出退出码 0 不能作为完成依据；恢复过程中还定位并修正了 QSPI 驱动调用的收发缓冲参数问题。

最终历史镜像 13299932 字节，Flash 读回 CRC32 为 `84cb6227`，未涉及尾部 CRC32 为 `15890968`；一次真实冷启动读到 BOOT_MODE=1，应用 `.text` 69876 字节逐字节一致，运行计时增长且保持 STOPPED。这些数值只属于该历史镜像，用于解释案例，不作为其他镜像的预期值。

## 失效条件和局限

该恢复程序绑定特定镜像、Flash 与驱动条件，不能把历史恢复步骤直接用于工具升级后的新产物。以上案例来自早期一次冷启动；后续外设交互与三次冷启动见 [2026-11-03 v19 验收记录](../board/results/v19_acceptance_20261103/README.md)。各记录保留自己的版本与测试条件。
