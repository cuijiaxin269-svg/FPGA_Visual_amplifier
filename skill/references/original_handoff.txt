## 首次接手

1. 读取 [state.json](state.json)，取得本次交接的时间、最后完成步骤、正式包、实际 load、录像目录和证据路径。它是**磁盘交接快照**，不是实时板卡状态。
2. 运行下方只读检查。它只检查清单内文件、当前录像目录的阶段标记及原始帧；不扫描工程、不连接硬件、不导入项目模块。`PASS` 仅说明交接文件与快照一致。若发现文件变化，定向阅读对应差异与后续日志，再更新状态；不能为了通过检查直接改掉预期 hash。
3. 根据最新用户请求选择下表的一条路线。普通接手只需本文件、state、自检摘要和该路线的参考；无需读取整个历史日志、全部参考或整个项目源码。
4. 首次汇报说明：最后已完成什么、仍未完成什么、下一步做什么、是否会操作硬件。若用户仅要求接手/解释/整理，沿用暂停状态；用户明确要求继续测试/修复时，可在已授权范围自主推进，无需逐步重复征求许可。

若 Python 路径变化，定向查找现有 Python 3 解释器；该检查器仅用标准库。迁移工作区时用 `--workspace 新目录` 只读检查，不能据此认定旧工具中嵌入的绝对路径或合同也已迁移。

## 共同边界

- 交接时用户已要求暂停。最新用户指令决定是否恢复；编写/使用 skill 本身不恢复实验。板上记录可能因之后断电或复位而失效，磁盘 raw 仍然有效。
- JTAG、USB 采集及板卡控制由当前接手的主 agent 统一安排；其他 agent 可以并行读源码、做离线分析。先排除其他活动控制者再访问硬件。
- 保留尚未处理的 clip：normal START、reset、重新下载和重新 RECORD 都可能覆盖现场。PROCESS 已请求或请求结果不明时，保留标记和日志，只走匹配工作流的观察/恢复分支，不能重复发 PROCESS，也不能读会清除 AP_DONE 的 HLS 状态。
- 已授权的历史下载是 JTAG 易失配置与 RAM 加载；不把它扩展为 Flash/SD 固化。正式包保持只读，变更放在独立候选目录，重新封包和验证后才上板。
- 原图/双画面是历史需求；当前目标是单画面运动输出，最终 live 目标为 band 3–12 Hz、alpha 30。当前离线实验使用 alpha 12，不能擅自改已有合同为 30。
- 570/270 串口屏已交给别人。旧 570 资料已进回收站，独立 270 工程未找到；HDMI 和 ZYNQ 验证仍属于本工程。清理记录见 state，不自动恢复或重建旧 HMI。

## 证据优先级

用户最新指令决定任务范围；当前现场读回决定易失状态；有时间和 hash 绑定的实际结果决定通过与否。`state.json` 指向最新已知结果，详细历史只在需要追因时查阅。

旧 README 中的“Host prepared / NO BOARD STAGE EXECUTED”和日志下方的“当前实际板上”可能是历史阶段。用它们理解接口，不用它们覆盖较新的实际 load、raw_manifest 和暂停记录。找不到或不一致时明确标为未知，局部补证。

1. 保留原运行目录，在新目录存新结果；写明原生命令退出码、成功/待定标记、失败原因，以及验证层级。
2. 更新 `D:/vision/ab12/docs/状态与验证进度_20261026.txt` 页首，必要时新增带日期的完整报告；历史失败不改写成成功。
3. 更新本 skill 的 `state.json`：时间、授权状态、当前工作流阶段、load/contract/recording 路径、相关 hash、允许出现的工作流文件及下一步。为新 raw 列表同步更新帧数和大小；已有 pause_receipt 保持历史只读，新暂停另留收据并更新引用。
4. 重跑检查；下一位 agent 应能从自检摘要定位唯一的下一步。已确认变化才更新期望值；对新阶段工件只记录存在，不把存在本身解释为阶段成功。

本 skill 的代码导航只在源码入口或正式构建方式变化时更新，不复制整个实验日志。
